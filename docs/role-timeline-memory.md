# 角色持续完善：基于原文证据的时间线记忆

## 目标

角色卡不应只在创建时生成一次。角色在聊天中命中的原文证据，可以持续沉淀为按章节排序的角色经历时间线；后续对话再按问题召回相关事件，让回答既更了解角色，也始终可追溯到原文。

适用对象是作品级“角色”，与剧情副本及剧情体验保持分离。

## 设计原则

- **原文优先**：每一条角色记忆必须保留对应章节与原文证据，模型抽取的结论不能替代原文。
- **时间有序**：章节号越小，事件越早；角色只能使用不晚于其“记忆截至章节”的内容。
- **增量沉淀**：只处理本轮 RAG 新命中的片段，不对整部作品重新抽取。
- **可控可审计**：抽取结果先作为候选事件去重、合并，再写入；用户能查看来源、修订或删除。
- **按需注入**：聊天时召回相关时间线，而不是把全部经历放进 Prompt。
- **不补写事实**：证据没有明确说明的事实保持未知；不得将推断写成原著既定事件。

## 角色数据分层

### 静态角色卡

创建角色时由“名称、别名、记忆截至章节”抽取，并允许用户编辑：

- 姓名、别名
- 背景、外貌
- 性格、口吻（私聊提示词内部使用）
- 参考图与桌宠相关资源
- 记忆截至章节

静态角色卡描述“这个人是谁”，不随着每次聊天无限增长。

### 动态角色时间线

时间线描述“这个人经历过什么”。建议每个事件保存：

```json
{
  "id": "event-id",
  "roleId": "role-id",
  "chapter": 1813,
  "title": "第一千五百三十六章 平静",
  "summary": "萧炎表示会替药老处理药族中的阻碍，承担保护老师的责任。",
  "keywords": ["药老", "药族", "守护", "责任"],
  "evidence": "萧炎的声音轻缓而平静……其余的任何事，交给弟子便可。",
  "sourceSegmentId": "segment-id",
  "status": "confirmed",
  "createdAt": "...",
  "updatedAt": "..."
}
```

`summary` 是基于证据的简明归纳，`evidence` 是可展示、可核验的原文片段；两者都要受章节上限约束。

## 对话中的采集流程

每次角色聊天完成 RAG 后，复用该轮已命中的原文片段：

1. 过滤掉超过角色记忆截至章节的片段。
2. 将片段与角色姓名、别名一起交给抽取模型，输出结构化“候选事件”。
3. 校验候选事件必须有明确原文依据，并记录来源分段与章节。
4. 按“角色 + 章节 + 事件语义”去重；相同事件合并来源，不能合并的事件分别保留。
5. 保存已确认事件并按章节升序维护时间线。

抽取日志应输出完整 Prompt、模型原始结果、解析后的候选事件、去重/合并决定与最终写入结果，便于排查错误归因。

## 示例：萧炎与药老

对于一次围绕药老的 RAG 命中，可形成如下时间线：

| 章节 | 事件 |
| --- | --- |
| 260 | 药老沉睡前鼓励萧炎；萧炎告别并立志成为强者。 |
| 399 | 萧炎承诺会变强、为药老清理门户。 |
| 659 | 萧炎成长为能独当一面的强者，感激药老一路教导。 |
| 1674 | 药老认可萧炎已超越自己、跻身大陆巅峰。 |
| 1813 | 萧炎主动承担保护药老、处理药族阻碍的责任。 |

因此，当用户追问“啥责任啊”时，系统可以优先召回第 1813 章的事件，并以较早的承诺与成长节点作为补充，而不是仅依赖字面命中“责任”的片段。

## 聊天提示词注入

角色聊天的上下文仍由“角色设定、用户设定、近期对话、当前 RAG 原文依据”构成。在此基础上增加一个独立区块：

```text
## 相关角色经历时间线
- 第 399 章：萧炎曾承诺变强、为药老清理门户。〔原文依据：...〕
- 第 1813 章：萧炎表示药族其余阻碍交由自己处理。〔原文依据：...〕
```

召回规则：

- 优先按当前问题和最近对话语义检索时间线事件。
- 默认注入少量最相关事件，并可补充一至两个必要的前置节点。
- 章节必须不晚于角色记忆截至章节。
- 时间线只补充事实与关系演变，不能覆盖当前 RAG 的原文约束，也不能推进剧情副本事件。

## 用户可见能力

角色详情中增加“角色经历”区域，按章节从早到晚展示：

- 章节、标题、事件概述与原文依据。
- 候选/已确认状态与来源。
- 单条编辑、删除、重新抽取入口。
- 记忆截至章节调整后，对超出上限的事件进行隐藏或重新校验。

首期可以先只展示已确认事件；候选审核流可作为后续增强。

## 实施顺序

1. 新增角色时间线事件的数据模型、接口与章节上限校验。
2. 在角色聊天 RAG 完成后增加候选事件抽取、日志、去重与持久化。
3. 在聊天检索中加入时间线事件召回，并将相关事件写入 Prompt。
4. 在角色详情提供时间线查看、来源展开、编辑和删除。
5. 为跨回合去重、章节上限、证据缺失、错误抽取与 Prompt 注入添加回归测试。

## 验收标准

- 同一 RAG 证据不会反复生成重复事件。
- 事件按章节升序展示，且不会越过角色记忆截至章节。
- 每个事件可追溯到明确的原文章节和片段。
- 新一轮聊天只带入与当前问题相关的时间线，不随时间无限膨胀。
- 时间线中的抽取结论不被当作无证据的原著事实。
